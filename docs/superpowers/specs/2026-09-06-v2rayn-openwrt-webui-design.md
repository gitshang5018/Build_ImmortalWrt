# OpenWrt 现代透明代理管理插件 (v2rayN-Wrt) 设计规格说明书

- **版本**: 1.0.0
- **日期**: 2026-09-06
- **状态**: 设计已批准 / 准备进入实现计划

---

## 1. 背景与设计目标

### 1.1 背景
v2rayN 是 Windows 平台上广受欢迎的科学上网图形客户端，因其直观的节点列表、极速真延迟测速、订阅管理及灵活路由深得用户青睐。然而，嵌入式路由器（OpenWrt）是无图形桌面的嵌入式 Linux 环境，无法直接运行依赖 .NET/Avalonia/WPF 的桌面程序。现有 OpenWrt 方案（如 PassWall、OpenClash 等）配置较为复杂、交互偏传统且资源占用参差不齐。

### 1.2 设计目标
打造一个**专为 OpenWrt 量身定制、现代化独立 WebUI 的轻量级代理管理套件（v2rayN-Wrt）**：
1. **视觉与交互**：采用响应式仪表盘设计（类似 Clash Verge / AdGuard Home 风格），支持电脑与手机浏览器端自适应，具备指标大卡片、实时节点卡片流及毫秒级测速徽章。
2. **轻量与独立**：采用 Go 编写的单二进制守护进程，将 Web 前端资源内嵌打包（`go:embed`），常驻内存控制在 15MB~25MB 以内。
3. **双内核驱动**：原生支持超低内存的 **Sing-box**（首选）与协议最全面的 **Xray-core**。
4. **高级流量调度**：完整支持**策略组**（最低延迟、故障转移、负载均衡、手动选择）与**链式代理**（前置中转跳板 + 落地出口）。
5. **深度生态协同**：DNS 分流支持无缝对接 OpenWrt 本地 **MosDNS**（如 `127.0.0.1:5335`），实现防污染、去广告与智能解析的最强组合。

## 3. 详细功能规格

### 3.1 策略组（Outbound Strategy Groups）
系统全面支持类似 Clash 的多级出站策略组，在 Web 界面中可视化配置：
* **最低延迟（UrlTest）**：后台定时（可配置探测间隔如 300s）对指定测速目标进行握手探测，毫秒级将流量自动切换至延迟最低的可用节点。
* **故障转移（Failover）**：按优先级排列节点，主力节点故障时代替，主力节点恢复后自动切回。
* **负载均衡（Load Balance）**：对大流量并发连接按轮询或源 IP 哈希分发至多个节点。
* **手动选择（Selector）**：支持在 WebUI 仪表盘上人工一键指定出口节点。
* **随机 / 稳定性优选**：支持随机散列分流与丢包率综合考量。

### 3.2 链式代理（Chain Proxy / 前置跳板）
支持在任意节点或策略组上配置「前置中转（Detour / Proxy Tag）」：
* 流量路径：`[局域网设备] -> [OpenWrt TUN] -> [前置中转节点 A] -> [落地出口节点 B] -> [目标网络]`
* 支持场景：专线中转跳板、原生 IP 落地解锁、家庭宽带 IP 伪装等。

### 3.3 DNS 分流与 MosDNS 深度对接
提供三种灵活的 DNS 处理模式：
1. **对接本地 MosDNS（推荐）**：
   - TUN 网卡将全部 DNS（53 端口）流量拦截后，直接转发至本机 MosDNS 监听端口（默认 `127.0.0.1:5335`）。
   - 由 MosDNS 完成国内白名单直连解析、分流 DoH、反追踪去广告后返回结果，与 ImmortalWrt 固件已有组件完美融合。
2. **内置智能 DNS 分流**：
   - 采用 Sing-box 原生 DNS 路由，国内域名走国内运营商 DNS，国外域名走 DoH 加密防污染解析。
3. **自定义外部 DNS 端口**：
   - 支持指定局域网任意 AdGuard Home 或外部递归 DNS 服务器。

### 3.4 局域网设备管理（LAN Control）
* 支持识别局域网活跃设备（IP、MAC、主机名）。
* 设备权限分配：
  * **全局走代理**（默认）
  * **绕过代理（纯直连）**：如 NAS、PT 下载机、IoT 物联网设备。
  * **指定出站节点/策略组**：如电视盒子固定走香港流媒体节点，办公电脑走专用低延迟节点。

### 3.5 断网保护与安全机制（Fail-Safe）
1. **配置预检（Pre-Flight Validation）**：
   任何节点、订阅或规则更改在落盘重载前，必须通过 `sing-box check` 模拟校验，校验失败自动回滚并报红，绝不应用错误配置。
2. **应急直连（Emergency Bypass）**：
   若策略组节点全部不可达，提供自动降级放行直连的选项，保障局域网基本通信不中断。
3. **OpenWrt procd 进程看门狗**：
   开机自启、守护进程异常退出 1 秒内自动 `respawn`。

## 4. RESTful API 接口规划

| 方法 | 端点 | 功能说明 |
|---|---|---|
| `GET` | `/api/status` | 获取系统状态（内核运行、内存占用、实时上下行速率、当前节点） |
| `GET` | `/api/nodes` | 获取全部节点列表与测速状态 |
| `POST` | `/api/nodes/ping` | 触发指定节点或全量并发测速 |
| `POST` | `/api/nodes/switch` | 切换当前出站节点 |
| `GET/POST` | `/api/subscriptions` | 订阅管理（添加、更新、删除、定时更新） |
| `GET/POST` | `/api/groups` | 策略组管理（创建 UrlTest/Failover/LoadBalance 组） |
| `GET/POST` | `/api/dns` | DNS 模式配置（对接 MosDNS 端口或内置分流） |
| `GET/POST` | `/api/devices` | 局域网设备管控规则（按 IP/MAC 分配分流策略） |
| `WS` | `/ws/traffic` | WebSocket 实时流量波形与连接数推送 |
| `WS` | `/ws/logs` | WebSocket 实时内核日志流推送 |

## 5. 测试与验证方案

1. **功能与单元测试**：
   - 针对 Base64、Clash 节点格式、VLESS Reality/Trojan/SS 节点 URL 编写解析器全覆盖用例。
   - 验证配置生成器渲染出来的 JSON 能够 100% 通过 Sing-box 官方语法检查。
2. **集成与网络验证**：
   - 在 OpenWrt 虚拟机中测试 TUN 网卡创建与自动路由生效。
   - 验证当上游 DNS 设置为 `127.0.0.1:5335` 时，MosDNS 能正常接收并高效解析请求。
   - 验证策略组在节点断网时的毫秒级故障转移与恢复行为。
   - 验证链式代理流量在多跳节点下的数据转发完整性。
